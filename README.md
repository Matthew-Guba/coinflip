# Coinflip

**Coinflip** – это простая онлайн‑игра «орёл/решка» с возможностью динамической настройки RTP (Return To Player).  
Сервер реализован на Go, использует PostgreSQL для хранения данных и предоставляет REST‑API для клиентской части.

## Особенности

- **Регулируемый RTP** – администратор может менять процент возврата игроку в реальном времени.
- **Provably Fair** – генерация серверного сида, его хэш и детерминированный roll‑флоат гарантируют честность результата.
- **JWT‑аутентификация** (подготовлена, но не реализована в примерах) и отдельный **admin‑токен** для управления RTP.
- **PostgreSQL** для надёжного хранения пользователей, ставок и истории раундов.
- **Docker‑compose** для быстрого развёртывания окружения (PostgreSQL + Adminer).

## Установка и запуск

### Предварительные требования

- **Go 1.22+** (для сборки без Docker)
- **Docker & Docker‑Compose** (для контейнерного развёртывания)
- **PostgreSQL 12+** (если используете локальную БД)

### Запуск через Docker Compose

```bash
# 1. Скопировать пример переменных окружения
cp .env.example .env

# 2. При необходимости изменить параметры в .env
#    (порт сервера, JWT‑секрет, admin‑токен, начальный RTP и т.д.)

# 3. Запустить контейнеры
docker compose up -d

# 4. Применить миграции (один раз)
docker exec -i coinflip_pg psql -U coinflip -d coinflip < internal/db/migrations.sql

# 5. Сборка и запуск Go‑приложения (можно в отдельном контейнере или на хосте)
go run ./cmd/server
```

Сервер будет доступен по адресу `http://localhost:8080` (порт берётся из `APP_PORT`).  
Для доступа к базе через веб‑интерфейс Adminer откройте `http://localhost:8081`.

### Запуск без Docker

```bash
# 1. Установить PostgreSQL и создать базу coinflip
#    (см. раздел «База данных» ниже)

# 2. Скопировать и настроить .env
cp .env.example .env
#    отредактировать переменные при необходимости

# 3. Применить миграции
psql $DB_URL -f internal/db/migrations.sql

# 4. Скомпилировать и запустить сервер
go build -o coinflip ./cmd/server
./coinflip
```

## Конфигурация

Переменные окружения задаются в файле `.env` (пример в `.env.example`):

| Переменная      | Описание                                 | Значение по умолчанию |
|-----------------|------------------------------------------|-----------------------|
| `APP_PORT`      | Порт HTTP‑сервера                        | `8080`                |
| `DB_URL`        | DSN PostgreSQL (формат `postgres://…`)   | —                     |
| `JWT_SECRET`    | Секрет для подписи JWT‑токенов           | `change_me_super_secret` |
| `ADMIN_TOKEN`   | Токен доступа к административным эндпоинтам | `super_admin_token` |
| `DEFAULT_RTP`   | Начальное значение RTP (в %)              | `97.0`                |
| `HOUSE_EDGE_MIN`| Минимальный процент «домашнего края» (не используется в текущей версии) | `1.0` |

> **Важно:** Файл `.env` добавлен в `.gitignore` – не коммитьте его в репозиторий.

## База данных

### Миграции

Все необходимые таблицы находятся в `internal/db/migrations.sql`:

- `users` – информация о пользователях и их балансе.
- `rounds` – история ставок, результаты и параметры честности.
- `rtp_config` – единственная строка с текущим RTP.

Для применения миграций используйте `psql` (см. выше) или любой клиент PostgreSQL.

### Пример создания пользователя

```sql
INSERT INTO users (username, balance) VALUES ('alice', 1000);
```

## API

Все эндпоинты находятся под префиксом `/api`.  
Ответы в формате JSON, статус‑коды HTTP соответствуют результату операции.

### Игровые эндпоинты

| Метод | Путь            | Описание | Параметры (JSON) |
|-------|-----------------|----------|------------------|
| `POST`| `/api/play`     | Сделать ставку | `user_id` (int64), `bet_amount` (float), `side` (`"heads"`/`"tails"`), `client_seed` (string), `nonce` (int64) |
| `GET` | `/api/balance`  | Получить текущий баланс пользователя | `user_id` (query) |
| `GET` | `/api/history`  | История последних раундов | `user_id` (query), `limit` (optional) |

### Административные эндпоинты

| Метод | Путь            | Описание | Требования |
|-------|-----------------|----------|------------|
| `GET` | `/api/admin/rtp`| Получить текущий RTP | Header `Authorization: Bearer <ADMIN_TOKEN>` |
| `POST`| `/api/admin/rtp`| Установить новый RTP | Header `Authorization: Bearer <ADMIN_TOKEN>`<br>Тело JSON: `{ "value": 98.5 }` (значение от 50 до 100) |

## Пример запросов

```bash
# 1. Сделать ставку
curl -X POST http://localhost:8080/api/play \
  -H "Content-Type: application/json" \
  -d '{
        "user_id": 1,
        "bet_amount": 10,
        "side": "heads",
        "client_seed": "myclientseed123",
        "nonce": 42
      }'

# 2. Получить баланс
curl "http://localhost:8080/api/balance?user_id=1"

# 3. Получить историю (последние 10 раундов)
curl "http://localhost:8080/api/history?user_id=1&limit=10"

# 4. Админ: посмотреть RTP
curl -H "Authorization: Bearer super_admin_token" http://localhost:8080/api/admin/rtp

# 5. Админ: изменить RTP на 99%
curl -X POST http://localhost:8080/api/admin/rtp \
  -H "Authorization: Bearer super_admin_token" \
  -H "Content-Type: application/json" \
  -d '{"value":99.0}'
```

## Тестирование

В репозитории пока нет готовых тестов, но структура проекта позволяет легко добавить их:

1. Создайте директорию `internal/game_test` и используйте `testing`‑пакет.
2. Для тестов с БД рекомендуется использовать отдельную тестовую базу и запускать миграции в `TestMain`.
3. Пример теста для расчёта win‑chance:

```go
func TestWinChance(t *testing.T) {
    SetRTP(context.Background(), 97.0)
    rtp := GetRTP()
    coeff := 2.0
    winChance := rtp / 100.0 / coeff
    if math.Abs(winChance-0.485) > 1e-6 {
        t.Fatalf("unexpected win chance: %f", winChance)
    }
}
```
